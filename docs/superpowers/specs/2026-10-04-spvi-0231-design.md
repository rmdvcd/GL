# Spec: SPVI 0.23.1 en GL (solicitudes SPVIR1 + licencias cortas SPVI2)

Fecha: 2026-10-04. Estado: diseño aprobado por el usuario; pendiente plan de implementación.

## 1. Objetivo

Actualizar GL para el protocolo SPVI 0.23.1. Las claves de GL NO cambian
(`gl.ecdh.p256.v1` descifra solicitudes, `gl.sign.ec.p256.v1` firma licencias).
Todo lo de SPVI anterior a 0.23.1 queda sustituido. El resto de apps conserva
intacto el flujo de envelope JSON v1.

## 2. Decisiones acordadas (no reabrir)

- Las licencias cortas SPVI2 se guardan en la tabla `licenses` existente
  (sin tabla nueva). Se distinguen por `version = 2` frente a `1`.
  `appName` se deriva del prefijo `SPVI:` del `deviceId` (el JSON v2 ya no
  trae `appName`). Todos los campos obligatorios de la tabla
  (`firstName`, `lastName`, `nationalId`, `phone`, `channel`,
  `requestedAtIso`, `nonce`) sí vienen en el JSON v2: no hace falta columna
  nueva para el registro.
- `.glreg` incluye las SPVI2 y las revalida por firma: nueva columna nullable
  `codigoCorto` (el código `SPVI2:` completo), incluida en export/import; al
  importar se verifica la firma ECDSA de `gl-sign-v1` por fila v2. Requiere
  Room v5. La verificación de firma NO necesita el secreto ECDH.
- El emisor NO corrige N: se emite el valor del JSON. Se eliminan los chips
  0–10, `selectedSecundarias`, `setSecundarias` y `ProponerSecundariasUseCase`
  (quedan inalcanzables: la única vía que producía una solicitud SPVI válida
  era v1 con `appName`, ahora rechazada).
- GL solo genera para las últimas versiones de cada app: un solo cuadro en el
  Generador, sin selector de modo. Reglas de detección confirmadas:
  1. Hay `SPVIR1:` → extraer el código (ignorar espacios/saltos, parar en el
     primer carácter fuera de `A-Z a-z 0-9 - _`) y resolver como SPVI 0.23.1.
  2. Sin `SPVIR1:` y texto con forma de envelope v1 → descifrar con el flujo
     actual; si la solicitud resultante es SPVI → «SPVI desactualizada: pide
     al cliente que instale SPVI 0.23.1 o posterior», sin emitir nada.
  3. Sin `SPVIR1:` y texto que menciona SPVI sin código extraíble o que no
     descifra → «No es una solicitud de SPVI 0.23».
  4. Cualquier otro texto inválido → «La solicitud no es válida» (actual).

## 3. Punto 0: limpieza

`git grep` confirmó que NO existe en el repo nada de `SPVI1`,
`licenciaCorta`, QR, PNG, Bitmap, zxing, `SPVIR1` ni `SPVI2`. La limpieza es
solo documentación: `CONTEXTO_LICENCIAS.md` sustituye la sección SPVI 0.22
por 0.23.1. No se toca nada de otras apps. Se añade prohibición explícita:
GL no genera ningún QR ni imagen (ver test e).

## 4. Cripto: `security/Spvi23.kt` (objeto puro, testeable en JVM)

- `contieneCodigo(raw)`, `extraerCodigo(raw): Outcome<String>`.
- `abrir(codigoB64, ecdhPrivada): Outcome<SolicitudSpviV2>`: decode, partir
  `epk(33) ‖ ct ‖ tag(16)` (tag = últimos 16 B), prefijo `02/03`, ECDH,
  `hkdfSha256(ikm, salt=epk, info="SPVI-R1", 44)` (el `deriveAesFromEcdh`
  existente da 32 B: insuficiente; usar `hkdfSha256` directo),
  clave = `okm[0..32)`, IV = `okm[32..44)`, AES-GCM con
  AAD = `"SPVI-R1|" ‖ epk` en crudo. Fallo GCM → `SpviDanada`.
  JSON con instancia local `Json { ignoreUnknownKeys = true }` (el global de
  `Di.kt` es `false`; no se toca).
- `sellarSolicitud(...)`: solo referencia de cliente + tests (patrón
  `ClientRequestHelper`), sin uso en producción.
- `cuerpo(...) : ByteArray(44)` (formato `0x02`, UUID crudo 16 B, huella 16 B,
  tipo, estado, secundarias, emitida/vence uint32 big-endian),
  `huella(deviceId, devicePub33)` = primeros 16 B de
  `SHA-256(UTF-8("SPVI-L2|" + deviceId + "|") ‖ devicePub33)` (verificada
  contra el vector: `fb445359b06179d282c7970ea4adab32`).
- `sellarLicencia(body, devicePub, firmaPriv, efimera: KeyPair? = null)`:
  efímera opcional para el vector determinista; ECDH, HKDF 44 B con
  info `"SPVI-L2"`, GCM con AAD `"SPVI-L2|" ‖ epk`; firma raw r‖s sobre
  `UTF-8("SPVI-L2|") ‖ epk ‖ ct ‖ tag` (intentar `SHA256withECDSAinP1363Format`,
  fallback DER→crudo).
- `formatearCodigo(...) = "SPVI2:" + b64url(epk‖ct‖tag‖firma)` → 157 B,
  **210 caracteres** (el pedido decía 216; el vector dorado mide 210 y cuadra
  al byte: fue confirmado por el usuario como 210).
- `verificar(codigo, firmaPub): Boolean` (para import y tests).
- Añadir `b64url` sin relleno y compresión/descompresión de punto P-256
  (no existen en `CryptoEngine`; no se modifica lo existente). Descompresión
  con la matemática del punto 2 del pedido; params P-256 de cualquier clave
  generada.
- `HybridBox`, `CryptoGatewayImpl` v1 y `CONTRACT_VERSION = 1` intactos.

## 5. Modelos y validación

- Nueva `SolicitudSpviV2` (`v`, `nombre`, `apellidos`, `ci`, `via`,
  `telefono`, `deviceId`, `tipo`, `solicitadaEn`, `nonce`, `devicePub` crudo
  33 B, `secundarias: Int` obligatorio, `renueva: String?`). Validación:
  `v == 2`, `deviceId` con prefijo `SPVI:`, `secundarias` 0–10 vía
  `Secundarias.validar(null, deviceId, …)`, `devicePub` punto P-256 válido,
  resto con las regex existentes.
- `Licencia.codigoCorto: String? = null` con `@EncodeDefault(NEVER)` (v1 lo
  omite, v2 lo exige). `validateLicense` ramifica: `v == 2` → reglas v2
  (`appName == "SPVI"`, secundarias no-null 0–10, fechas ISO, perpetua sin
  vence); `v == 1` intacto. `validateRequest` sigue rechazando `v != 1`.
- `GenerarLicenciaUseCase`: guardia que devuelve `SpviDesactualizada` si la
  solicitud v1 es SPVI (defensa en profundidad: jamás emite larga a SPVI).
- Puerta nueva `SpviPuerta` (`abrirSolicitud`, `emitirCodigo`) implementada
  por `CryptoGatewayImpl` con las claves Keystore sin exportarlas;
  `emitirCodigo` se autoverifica tras sellar. `SeguridadRepository` v1
  intacto.

## 6. Emisión y renovación: `EmitirSpvi2UseCase`

Entrada `SolicitudSpviV2` + pago. Resuelve `renueva` contra
`LicenciaRepository.getById`: existe + mismo `deviceId` + no revocada + no
perpetua → `vence = max(ahora, prevVence) + days`, `emitida = ahora`
(fechas truncadas a segundos); si no, emisión normal + flag
`renuevaIgnorada`. Construye `Licencia(v=2, appName="SPVI", estado
ACTIVA/PERPETUA, precio = total, nonce nuevo)` y pide el código a la puerta.
Salida `(licencia, mensajeRespuesta, renuevaIgnorada)`.
Duraciones: `type.days()` (30/180/365). Nunca se usan fechas del cliente.

## 7. Registro y `.glreg` (Room v5)

- `LicenseEntity.codigoCorto TEXT` nullable + `M_4_5` + mappers + test de
  migración v4→v5 + `schemas/5.json`.
- `exportar` incluye v2 tal cual (validación estructural); `importar` además
  verifica `Spvi23.verificar` por fila v2 → si falla, `ImportFailure`.
- Filas v1 antiguas (incl. SPVI v1) siguen importando igual.

## 8. VM y UI

- ViewModel: salen `proponer`, `selectedSecundarias`, `setSecundarias`; entran
  `spvi: SolicitudSpviV2?` + `renuevaAviso`. `onRawChange` aplica las 4 reglas
  (§2). Portapapeles acepta `SPVIR1:` además de `"alg"`. `generateLicense`
  ramifica al mensaje SPVI2 con share WhatsApp/SMS solo-texto.
- Pantalla: sale el bloque de chips; entra panel de datos descifrados +
  desglose de precio solo-lectura + aviso de `renueva` ignorada; botón
  **«Pegar»** junto al campo; tarjeta de respuesta solo-lectura con
  **«Copiar mensaje»** (visible solo para SPVI; el flujo v1 no cambia).
- Mensaje de respuesta exacto (§4 del pedido): 6 líneas + renglón en blanco +
  código; fechas `dd/MM/yyyy` en `America/Havana`, sin tildes ni ñ;
  «Vence: nunca» si perpetua. Sin QR ni imágenes.

## 9. Errores y strings

- `SpviNoEs023` («No es una solicitud de SPVI 0.23.»),
  `SpviDesactualizada` («SPVI desactualizada: pide al cliente que instale
  SPVI 0.23.1 o posterior»), `SpviDanada` («solicitud dañada o no es para
  GL.»); aviso renovación: «Renovación no aplicada: se emitió como licencia
  nueva.».
- strings `pegar`, `copiar_mensaje`, etiquetas del panel SPVI.

## 10. Tests (TDD, puntos a–e del pedido)

- `Spvi23VectorTest`: huella/cuerpo/epk/ct‖tag byte a byte con efímera fija,
  firma verificada con la SPKI de prueba (nunca comparada), mensaje exacto.
- `Spvi23SolicitudTest`: roundtrip sellar/abrir + mutación de 1 B en
  epk/ct/tag falla.
- `RenovacionSpviTest`: anterior vence en 5 días → MENSUAL vence a los 35;
  vencida hace 3 días → 30 desde ahora; otro deviceId/revocada → se ignora
  + aviso.
- `ExtraccionSpviTest`: código partido en varias líneas abre igual; sin
  `SPVIR1:` o envelope v1 antiguo → avisos del §2.
- `SpviMensajeTest`: formato exacto (6 + blanco + código), fechas Havana,
  «Vence: nunca»; ausencia de QR (sin dependencia zxing, sin código de
  imagen).
- Además: migración v4→v5, validador v2, guardia anti-larga, VM con puerta
  fake. Recount de XML al final (`testDebugUnitTest --rerun`).
