# Operar el directorio de confianza v1

Usa Node 22 o posterior en un equipo offline. Los comandos siguientes se ejecutan con `node tools/directorio/cli.js`. Guarda todos los archivos operativos **fuera del repositorio**, con acceso exclusivo. Para cargar una passphrase sin eco en Bash: `read -rs DIR_PASSPHRASE; export DIR_PASSPHRASE`. Al terminar: `unset DIR_PASSPHRASE`.

1. Ejecuta `gen-root --out raiz-A.key.enc` y repite para B con otra passphrase. Guarda dos copias cifradas offline; conserva la passphrase en papel por separado. Entrega por un canal autenticado ambas SPKI y huellas (`RAIZ_A_SPKI`, `RAIZ_B_SPKI`) a quien prepara los builds de Shalev. Nunca entregues las privadas. El vector de `vectores/directorio-v1.json` **no** es una raíz de confianza.
2. En GL → Claves copia ambas entradas a archivos JSON separados. Inicializa `bootstrap-from-trust --out directorio.src.json`. Por cada entrada usa `add-key --src directorio.src.json --entry entrada.json`. Para canje añade la pública del servicio con `add-key --src directorio.src.json --kid gl-redeem-v1 --uso canje --spki <SPKI> --desde <epoch_s>`. Verifica todas las huellas por otro canal.
3. `sign --src directorio.src.json --root raiz-A.key.enc --raiz A --out directorio.json`. Conserva el **src actualizado**: lleva el contador de secuencia. `verify --file directorio.json --root-pub <A> --root-pub <B> [--previous directorio-anterior.json]`. Embebe la primera versión verificada como `directorio-bootstrap.json`; publica `directorio.json` en la release `revocaciones` de `<REPO_SHALEV_RELEASES>`. Un bloqueo `.lock` tras una interrupción solo debe retirarse tras comprobar que no hay otro proceso operando y revisar el último seq publicado.
4. Al reinstalar/cambiar GL, primero actualiza cada entrada vieja (`estado: retirada`, `hasta`: segundo del cambio, misma SPKI y `desde`). Después añade las nuevas y firma/publica con seq superior. El cliente verifica los bytes exactos de `SPVI-DIR1|` + `datos` con A o B, acepta el mayor seq verificado entre bootstrap y caché y solo admite empate con `datos` idénticos. Límite 64 KiB; P-256, huellas SHA-256 del DER, como máximo una ECDH vigente. Las claves de firma retiradas solo validan dentro de su ventana; las ECDH retiradas no cifran nuevas solicitudes.
5. Compromiso: `estado: comprometida` con la misma SPKI, firma y publica, avisa a los clientes y reemite las licencias. Retirar sin marcar el compromiso no impide firmar con fechas antiguas. Si A se compromete, firma con B y sustituye A por C en el siguiente build. Un atacante con raíz y passphrase puede firmar directorios hasta que los clientes dejen de confiar en esa raíz.
